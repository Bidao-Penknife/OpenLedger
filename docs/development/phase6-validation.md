## 原生桌面与冻结数据验证

全部验证采用新建的独立合成账本，没有读取默认用户财务目录。

合成统计期间为 2026-08-01 至 2026-10-03：收入 10,000.00 元、毛支出 213.00 元、退款 28.00 元、净支出 185.00 元、结余 9,815.00 元。8 月无交易，月度趋势补零；退款计入 10 月，转账与期初排除于收支。包含期初的总资产为 10,815.00 元。

桌面真实文件流程读取 3 行账单：一条疑似重复支出、一条收入、一条无效负金额。预览未写库，疑似重复默认不勾选，无效行不能勾选；明确勾选前两行确认后，总资产变为 13,790.00 元。整批撤销后恢复 10,815.00 元，保留批次历史和导入身份。实际通过页面生成 CSV、XLSX、三页 A4 PDF 与 PNG，浅色、深色及 880×600 最小窗口已检查截图。

取消竞态回归使用真实确认流程：准备 payload 已完成但 Qt 队列尚未交付时点击取消，不发出资金命令，余额与原预览保持。相同源交易 ID 的金额、类型或外部身份矛盾会阻止候选；无效首行不会误占退款依赖；已入库原支出可被新的退款正确关联。

冻结 exe 在仅含 Windows 系统目录的 PATH、不同工作目录下重开上述已填写账本，资金数据库 SHA256 不变。CSV/XLSX 均导出 8 笔有效交易，字段逐值一致，已撤销批次的两笔交易不计入有效导出。冻结程序实际生成 PDF/PNG，并完成备份、新目录恢复、已存在备份拒绝及损坏备份拒绝。恢复后的 10 笔历史交易、11 笔分录、23 个回执、28 个审计及 1 个已撤销批次全部保留；桌面 `settings.json` 仍不属于资金备份。

冻结引擎检查及备份恢复不等于所有业务控件都在 exe 中被人工逐项点击；完整确认/撤销控件流程由源码原生窗口与自动 UI 测试验证。当前机器具备 Python，尚未执行干净 Windows 虚拟机验收或真实系统输入法选词全流程。
