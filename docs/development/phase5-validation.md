# 阶段 5：规则解析与桌面记账验收

日期：2026-10-02。版本：`0.1.0.dev0`。OLG-015–019 已完成本地验收；阶段 6 尚未开始。本阶段把已验证的资金核心接入可操作桌面，保留阶段 3/4 历史记录。

## 实现范围

| 任务 | 实际实现 |
| --- | --- |
| OLG-015：本地解析 | 纯函数式规则入口、金额与中文金额、相对/具体日期、时段与精确时间、分类建议、支付渠道、对象、原文证据；多金额、冲突及不支持内容保留问题 |
| OLG-016：可编辑草稿 | Enter 解析、输入框 Ctrl+Enter 确认；合成 IME 预编辑保护；修订号校验、手工覆盖优先、多笔选择、已保存候选标记、必填校验、失败保留与重复提交拦截 |
| OLG-017：交易页面 | 账本/账户/类型/日期/文字筛选、稳定排序与分页、变化序列刷新、编辑、软删除/恢复、退款入口；版本冲突保留表单 |
| OLG-018：账户与资料 | 账户、账本、分类、标签、支付渠道的创建/编辑/归档/恢复；默认项和显式账户映射；转账、退款、期初修改与余额校准表单 |
| OLG-019：基础主题 | 简洁中文 Qt Widgets 页面、浅色和深色主题；IANA 记账时区及主题原子持久化，界面字符串保留 `tr()` 入口 |

金额以整数分保存；支付渠道与资金账户分别处理。分类属于建议，“火锅”不生成已确认地点。初始业务时区为明确显示的 `Asia/Shanghai`，可在设置中修改。`LedgerService.time_zone` 与桌面时区同步，账户起算日期与交易日期采用一致的业务日期；历史交易保留自己的时区。

## 代码结构与边界

```text
src/openledger/
├── application/dto/parsing.py       # 不可变请求、候选、字段来源与证据
├── application/parsing.py           # 本地规则；无 Qt、网络或数据库写入依赖
├── application/dto/queries.py       # 筛选、分页与总览结果
├── infrastructure/queries.py        # 同一 SQLite 快照中的行数、记录与修改序列
├── infrastructure/settings.py      # 可选桌面偏好；原子文件替换
├── presentation/commands.py         # 单线程 writer 与 GUI 队列信号
└── presentation/views/
    ├── main_window.py              # 总览、草稿、页面协调与设置
    ├── transaction_form.py         # 可编辑字段与 IME 输入框
    ├── transaction_edit.py         # 版本化交易编辑及校准说明
    ├── transactions.py             # 筛选、分页与明确操作
    └── management.py               # 资料和专用资金表单
```

界面先验证可见表单，再经 `CommandBridge → LedgerWriter → LedgerService` 提交。Qt 信号在 GUI 线程处理成功或失败；余额只在已提交回执后刷新。相同失败意图保留请求 ID，修改载荷则生成新请求 ID。正在提交时禁用业务页面，关闭窗口等待运行中的提交完成。编辑保留来源、原文和预期版本；交易对话框使用窗口模态及活动对话框保护。

本阶段没有修改 `0001.sql` 或创建新迁移，阶段 4 的模式与摘要保持不变。`settings.json` 只保存主题和记账时区，不进入资金备份；恢复到新目录后重新设置。

## 实际检查结果

环境为本机 Windows x64、CPython 3.12.5、PySide6/Qt 6.11.2、SQLite 3.45.3，依赖使用 `uv.lock`。数据库继续采用经过验证的 DELETE 日志模式。

- 最终 pytest：**449 项全部通过**，217 单元、183 集成、49 Qt UI；耗时 83.11 秒，无跳过、失败或错误。证据为 `build/validation/phase5-pytest.xml`。
- Ruff lint、格式检查、strict mypy、锁文件检查和 Git 暂存内容空白检查通过；质量日志随本阶段制品提供。
- 本地解析器的 88 项规则测试覆盖原文位置、中文金额、跨日期、时段、夏令时重叠/缺失、多事件及账户映射。解析不写数据库。
- 新查询集成测试使用真实 SQLite 文件验证同一快照内的分页总数/行/序列、并发提交、字面通配符搜索、退款发生月、归档及超 int64 的月度流水精确汇总。
- 桌面流程测试验证自然语言确认、真实管理表单提交、失败重试、输入变化、手工覆盖、精确时间展示、渠道映射、编辑、删除恢复、旧版本冲突和业务时区跨日边界。
- 桥接测试包含“数据库已提交但返回结果丢失”的故障，重试只回放一份回执，不产生第二笔资金记录。设置测试包含 `fsync` 与文件发布失败，保留旧文件并清理临时文件。
- 源码、冻结 exe、ZIP 解压后的 exe 均通过原生 `windows` Qt 平台启动验证；使用独立中文与空格路径、正常创建 HWND 并关闭。冻结与解压启动的 PATH 仅包含 Windows 系统目录。
- 默认启动 smoke 验证没有自动创建账户或资金记录，只初始化默认账本与基础资料。

额外桌面验证在独立合成账本中先建立 1,000.00 元期初余额。解析 128.00 元火锅支出时余额保持不变；明确确认后变为 872.00 元；转账 25.00 元后总资产不变；退款 28.00 元后总资产为 900.00 元，两个账户分别为 847.00 和 53.00 元。形成 4 笔交易、5 条账户流水、16 份命令回执和 17 条审计。浅色/深色草稿、交易页面和账户页面截图均已实际渲染并检查。

冻结程序重新打开上述合成账本后，源数据库摘要没有变化。冻结备份与新目录恢复保留相同金额、流水、回执和审计；已有备份拒绝覆盖，损坏备份拒绝发布目标，主题设置不进入资金备份。这些测试只使用合成数据，交付验证 ZIP 不包含数据库或账本备份文件。
