# OpenLedger APK 功能清单与后续路线

整理日期：2026-10-06。当前 APK：`0.1.0-alpha1-preview`，包名 `org.openledger.android.preview`。本文件整理现状与后续工作，没有新增应用功能。

当前版本已经形成“输入 → 解析草稿 → 核对并确认 → 保存 → 查看流水与资产 → 重启保留”的本地记账流程。Windows 与 Android 共享 Python 资金核心，但手机界面只接入了部分用例；桌面已有功能不能据此记为 APK 已实现。

## 目前可以使用

| 功能 | 手机实际支持范围 |
| --- | --- |
| 自然语言记账 | 本地中文规则解析；例如输入“咖啡 25元”，得到可修改的草稿，确认后保存 |
| 手工收入、支出 | 新建记录时选择类型、金额、账户、账本、分类与支付方式 |
| 日期与时间信息 | 日期选择、上午/中午/下午/晚上/夜间；解析产生的精确时间可保留；记账时区固定为 Asia/Shanghai |
| 补充信息 | 备注、对象、商户、地点；无法可靠解析的字段由用户补充 |
| 多账本 | 创建账本，新建记录时选择账本 |
| 账户与期初余额 | 创建现金、银行卡、微信、支付宝或自定义账户，明确期初余额与起算日期 |
| 流水 | 查看已保存记录，文本搜索，按 25 条分页 |
| 资产与收支 | 各账户余额、总资产、本月收入和支出汇总 |
| 本地保存 | SQLite 存在应用私有目录，离线可用；重启后保留已保存记录 |
| 防止重复记账 | 已确认命令持久化；使用 UUID 回执，失败重试与重启恢复避免重复扣款 |
| 中文与主题 | 中文界面、跟随 Android 系统明暗主题；文本集中在资源文件 |

多金额或多事件输入暂时转为手工录入，手机没有逐笔拆分确认流程。付款渠道与资金账户分别确认，选择“微信支付”不会自动猜测应扣哪个账户。

## 还未实现

| 功能组 | 缺少的手机功能 | 建议优先级 |
| --- | --- | --- |
| 备份与恢复 | 导出完整账本备份、校验并恢复备份、换手机迁移；两端备份互通尚待验证 | P0，首先完成 |
| 已保存交易维护 | 编辑金额/日期/账户等字段、删除、恢复已删除记录；当前“编辑草稿”只针对保存前的新记录 | P1 |
| 资金操作 | 账户间转账、关联支出的退款、余额校准表单 | P1 |
| 资料管理 | 账户/账本改名与归档、恢复，分类增删改与归档，标签管理，支付方式与默认账户映射 | P1 |
| 查询筛选 | 在手机界面按账本、账户、分类、类型、日期范围组合筛选；现有文本搜索已支持 | P1 |
| 完整统计 | 月度收入/支出趋势、分类占比、消费排行、期间比较和财务分析报告；现有本月汇总已支持 | P2 |
| 导入与导出 | CSV/Excel 列映射、预览、重复检测、确认导入与撤销，CSV/Excel 导出，PDF/图片报告 | P2 |
| AI 解析 | 用户配置 OpenAI 或兼容 API、模型与凭据、明确触发 AI 解析；本地规则解析已支持 | P2 |
| 设置与更新 | 手动选择浅色/深色、英文翻译与语言切换、记账时区设置、GitHub Release 更新提醒 | P2 |
| 手机快速入口 | 桌面小组件、快捷方式或快捷设置磁贴；当前需要打开应用进入快速记账页 | P3，可选增强 |
| 图片附件 | 添加、查看与管理图片；第一版需求仅要求预留接口 | 后续扩展 |
| 同步与扩展 | 手机/Windows 数据交换与冲突处理、云同步、手机可配置插件入口；没有插件市场 | 后续扩展 |

自动读取微信、支付宝或银行通知、截图 OCR 与语音记账没有实现，也不属于当前首个 APK 的交付范围。应用当前没有网络权限，手机与 Windows 各自保存账本。

## 建议开发顺序

以下版本号是建议里程碑，不代表已经实现或承诺发布日期。后续实现继续按阶段验收。

| 里程碑 | 主要范围 | 完成判据 |
| --- | --- | --- |
| A：0.1.0-alpha2 | 本地完整备份、文件选择、校验与恢复 | 真实 Android 中备份后恢复到账本新目录，资金记录/余额/Schema 一致；损坏、错误版本与重复目标安全拒绝；失败保留原账本；再验证 Windows 备份互通 |
| B：0.1.0-alpha3 | 编辑/删除/恢复、转账/退款、余额校准、资料管理与筛选 | 每项资金操作复用共享事务；验证原子性、幂等重试、余额与退款关系；手机界面完成操作与重启复核 |
| C：0.2.0-beta1 | 统计图表、CSV/Excel、PDF/PNG | 统计与共享核心一致；导入先预览再确认，整批成功或回滚，验证重复与撤销；导出文件可重新读取且保留金额精度 |
| D：后续 beta | 可选 AI、设置与更新提醒、手机快速入口 | AI 默认关闭，用户自行配置，结果只生成可确认草稿；设置可持久保存；快速入口复用同一记账流程 |
| E：移动稳定版 | 固定正式签名、预览数据迁移、真机与兼容性验收 | 先完成恢复能力，再验证同签名升级、旧数据保留、ARM64 真机与最低系统版本、中文输入法及低存储场景 |

跨端同步另立里程碑：先定义数据标识、修改日志与冲突策略，再实现同步传输；直接覆盖另一端 SQLite 文件不能当作同步。

目前后续工作的总 Issue 是 [#6：Android 下一阶段功能与恢复能力](https://github.com/Bidao-Penknife/OpenLedger/issues/6)。开发上述里程碑时再拆分具体实现 Issue；本次仅整理功能。

## 运行与发布状态

| 项目 | 已有证据 | 尚待验证或完成 |
| --- | --- | --- |
| Python 测试 | 本机与已完成 Windows CI 均记录 1021 项通过，包含 33 项移动桥接测试 | 新增功能需要补充对应测试 |
| Android 设备测试 | Android 15 / x86_64 模拟器中 5 项实际通过，离线记账与强制结束后冷启动保留通过 | ARM64 真机、Android 7 运行、真实中文输入法长时间使用、低存储与更多进程终止竞态 |
| Android CI | APK 构建、格式、Lint 与静态制品检查通过 | CI 没有执行 Android 设备测试；Lint 为 0 错误、8 警告 |
| 安装与签名 | Android 7.0 起，ARM64 / x86_64；当前 APK 使用本机调试签名 | 32 位设备不支持；正式发布签名与数据迁移流程未完成 |
| 数据恢复能力 | 重启保留已保存账目 | 还没有手机备份；卸载或清除应用数据会删除手机账本 |

因此，下一步优先做备份恢复，再补交易维护与资金操作，随后扩展统计和文件交换。
