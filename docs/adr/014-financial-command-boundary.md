# ADR-014：资金命令、默认偏好与恢复边界

状态：阶段 4 已采用。日期：2026-10-02。

## 决策

展示层依赖 `application.ports.ledger.LedgerPort`，数据与结果通过 DTO 或独立快照返回；SQLite 适配器 `infrastructure.ledger.LedgerService` 负责协调引用校验、领域值规则与单次短事务。领域层不导入 Qt 或 SQLite。同步命令可通过 FIFO `LedgerWriter` 排队，连接在执行线程内创建并关闭；排队时深复制意图，待执行任务取消后不写入，已提交结果不能伪装成取消。

所有持久化管理与资金操作走统一命令边界：规范化语义字段并计算 hash，在写锁内先查回执，再校验当前状态和 expected_version。交易头、全部流水、标签、审计、change_log 和回执一次提交；无变化的校准也保存回执。普通业务失败不保存成功回执。原始错误不向界面暴露 SQL 或账目。

UUID 在实际 Python v1 接口中使用规范字符串，日期使用 date，精确时间使用 aware datetime；服务在 hash 和日期校验前统一到 UTC 毫秒。它落实阶段 2 的标准 JSON 表示，同时便于未来 Qt model 使用。更细精度会截断，不根据模糊时段虚构时刻。默认业务时区为 UTC，可构造服务时显式注入 IANA 时区；阶段 5/7 将接入用户配置，不从本机用户名或中文界面猜测时区。

`app_preferences` 单行表保存默认账本/账户 ID。默认实体归档时必须在同一命令提供活跃 replacement_default_id；偏好切换和实体归档同事务提交。默认状态包含在该聚合审计快照中。不能以配置文件与数据库分别写入的方式声称跨资源原子性。

余额从未删除交易的有效流水计算，归档账户仍参与总资产。Python int 流式精确求和后检查 signed int64，不依赖可能先溢出的 SQL SUM。零期初不创建零金额交易，仍保存切点；活跃期初至多一笔。校准只创建今天的固定差额，历史补录不会暗中重算。

## 恢复与验证

启动、备份与恢复额外检查 SQLite 外键无法表达的资金关系：交易流水数量与方向、转账守恒、期初唯一性与切点、退款存活/日期/累计额度、校准快照、分类层级、默认偏好与整数聚合范围。只读检查拒绝异常，不自动改账；它不构成防恶意篡改的审计认证。

首版恢复仅允许新目录或空目录：同卷暂存、完整校验、发布新数据目录并保存恢复收据，旧目录保留。关闭应用后显式切换 --data-dir；未实现在线原库覆盖、自动切换或回滚恢复向导。附件录入尚未开放，备份已验证所有数据库引用的保留附件。

日期与回执、并发重试、各写入步骤失败、归档保留引用、退款依赖、迁移损坏拒绝、备份篡改和恢复失败由实际临时库测试验证。测试清单和本机结果见阶段 4 验收记录。
