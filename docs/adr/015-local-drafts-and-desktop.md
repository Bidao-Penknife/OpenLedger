# ADR-015：本地草稿、桌面确认与设置边界

状态：阶段 5 已采用，统一验收已完成。日期：2026-10-02。

## 问题与约束

桌面自然语言录入需要快速显示建议，同时保持阶段 4 的资金事务、幂等性和恢复边界。解析结果可能缺字段、包含多个金额或受时区影响；它不能直接成为写入命令。Qt 事件循环需要处理中文输入法、重复按键和 worker 返回结果，不能在界面线程内执行网络请求或绕过版本校验。

阶段 5 的范围为纯本地规则、日常记账和基础主题；AI、完整统计、导入导出、托盘、全局热键、系统主题、云同步和安装器保留后续阶段。阶段 2 历史设计与阶段 4 已应用 SQL 保持原样，本阶段不因桌面外观偏好修改资金 Schema。

## 决策

`application.dto.parsing` 定义冻结的 ParseRequest、ParseResult、ParsedDraft、FieldCandidate、Span 和 ParseIssue。`application.parsing.LocalParser` 是同步、纯本地服务，仅接受调用方注入的 reference_date、IANA 时区和精简资料候选，不读取系统时钟、完整账目或余额，不持有 writer，不调用网络。类别/账户/支付渠道只返回输入候选中的标识，不创建资料。

金额使用整数分，不四舍五入超精度值。原文字符索引用于证据，等长全角字符转换保持 span 对应原文；不通过删除空白后的索引展示证据。字段记录 explicit、rule_suggestion 或 default 来源和可选替代值，不显示未经校准的置信度百分比。未知地点和商户保持缺失；“火锅”支持餐饮建议与备注，不成为地点。

支付渠道与资金账户分开。渠道账户映射必须来自用户明确配置；一般默认账户只能作为可见建议。多金额保留所有候选，多事件由用户逐笔选择并确认，无法确定事件关系时保持 ambiguous。转账和退款进入专用表单，不从普通自然语言草稿直接写成资金操作。

日期、时段和精确时间独立表示。相对日期使用注入的业务日期，模糊时段不生成 UTC 时刻；具体当地时刻经过 ZoneInfo 转换，夏令时 fold/gap 必须处理。解析器只掌握 reference_date，同日未来精确时刻由资金服务在提交时再次校验，解析成功不代表保存校验成功。

表现层维护 draft_id 和 revision，输入、上下文或字段更改后修订号递增；只允许当前草稿结果应用。用户字段优先于解析建议。QuickInput 获得焦点时，Enter 解析、Ctrl+Enter 明确保存、Shift+Enter 换行；组合输入状态、自动重复按键和正在提交状态会阻止这些触发。按钮提供相同的显式操作，没有全局快捷键。

确认表单校验字段后组装写入 payload，资金变更经 `presentation.commands.CommandBridge` 和既有 FIFO LedgerWriter 提交。桥接通过 queued Qt signal 把已提交 MutationResult 或安全错误代码送回界面；同一未更改意图失败后复用 request_id，成功后清除重试意图。正在保存时界面暂停新提交，退出等待运行中的短事务。原类型、source 和 source_text 在编辑时保留，审计与乐观版本检查仍由资金服务负责。

读模型由 `infrastructure.queries.LedgerQueries` 在单个 SQLite 读快照内组装计数、交易页及 change_seq，按业务日期、创建时刻和 ID 排序；每次翻页或刷新重新读取快照。本阶段使用有界 OFFSET 分页，不宣称不同页在并发变更中共享固定数据库快照。总资产包含归档账户，月度净支出按退款实际发生月扣减；资产与资金求和使用 Python 整数和既有范围校验。

桌面组件目前使用具体 LedgerService 查询资料和组装表单，命令桥接依赖 LedgerPort；领域层及解析层仍与 Qt、SQLite 分离。这是当前交付的边界，不声称已经实现所有阶段 2 的查询/provider Protocol 或完整插件系统。

主题与记账时区采用 `infrastructure.settings.DesktopSettings` 和 SettingsStore。默认浅色与 `Asia/Shanghai` 在界面明确显示，用户可选择有效 IANA 时区；不从 Windows 用户名或中文界面猜测区域。时区变化使未保存的自然语言草稿失效，已保存记录保留原时区。

`settings.json` 通过同目录临时文件、flush/fsync 和原子替换写入。它只包含主题和时区，不包含余额、默认实体引用或 API 凭据。资金默认账本/账户仍在 app_preferences 中随命令原子保存，桌面设置不进入资金备份；恢复到新目录后重新核对设置。缺失或无效的可选设置采用已说明的默认值。

## 后果与验证

首次使用需要明确创建账户并填写期初，包括零余额；解析缺少账户或其他必填项时无法静默完成入账。保守规则遇到歧义需要重写、逐笔选择或手工录入，这比猜测资金信息增加一步确认。

本阶段没有新增 Schema 迁移，资金一致性仍由阶段 4 服务保证。主题与时区设置具有独立文件原子性，不被描述为与资金数据库共同事务；未保存草稿不持久化，也不承诺跨退出恢复。

测试覆盖应包含金额和证据边界、时间/DST、多事件、IME 与重复提交、默认/映射、错误保留、交易版本及查询口径。实际检查数量、原生窗口、冻结程序和解压包的本次结果统一记录在[阶段 5 验收记录](../development/phase5-validation.md)，不得以历史阶段测试或仅存在 CI 配置推定已完成验证。
