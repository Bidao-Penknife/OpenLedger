# 日常记账指南

本文对应 `0.3.0.dev0` 的现行桌面交互。首次启动和数据目录见[启动指南](getting-started.md)，阶段 7 当前统一验收状态见[本阶段记录](../development/phase7-validation.md)；[阶段 5 记录](../development/phase5-validation.md)保留基础交互建立时的历史结果。当前支持人民币，金额按整数“分”保存，普通收支金额必须大于零且最多两位小数。

## 建立账户和账本

“账户与管理”可切换账户、账本、分类、标签和支付渠道，分别进行新建、编辑、归档或恢复。初始账本为“我的账本”，可以再创建旅行、学习或家庭账本。账本用于组织收支，资金账户用于计算实际余额；不同账本共用同一个资金账户时，该账户余额包含全部有效流水。

新建账户必须填写账户类型、开始记账日期和该日期的期初余额。期初表示这一天开始时已持有的资金，不能把当前余额和准备补录的历史交易重复计入。余额为零时填 `0.00`；期初允许负值。开始日期之前的交易会被拒绝。

可以将活跃账户和账本设为默认项。归档默认项时需要选择新的活跃默认项；若没有其他可用项，先创建。归档保留历史记录和账户余额，已归档账户仍计入总资产。资料恢复后可再次用于新交易；类别最多两级，父子类型必须一致。

支付渠道的“建议付款账户”是显式关联。只有自行配置后，“微信支付”才会建议映射到账户；未配置时不凭渠道名称或同名账户推断资金来源。一般默认账户与渠道映射都作为可见建议，在保存前核对。

## 自然语言录入与确认

在“总览与记账”输入一句话，点击“解析草稿”或在输入框内按 Enter。例如：

```text
昨天晚上和朋友吃火锅花了128元，微信支付
咖啡 25元
收到工资5000元
```

第一句会建议支出、128 元、昨天、晚上、餐饮和微信支付，并识别对象“朋友”。“火锅”保留为消费描述，不成为已确定地点或商户。“昨天晚上”只保留日期和时段，不编造精确时间。缺少账户或分类时手动补齐。

草稿可编辑类型、金额、日期、时段、资金账户、账本、分类、支付方式、对象、商户、地点、备注和标签。右侧标注识别、规则建议和默认值；用户修改的字段优先。输入原文或时区变化后，原自然语言草稿失效，需要重新解析或明确选择手工录入。

核对必填项后点击“确认保存”。仅当自然语言输入框有焦点时，Ctrl+Enter 触发同一确认动作；Enter 只解析，Shift+Enter 换行。中文输入法组合输入、自动重复按键或正在保存时不会触发新的提交。默认全局快捷键 Ctrl+Alt+L 打开独立快速窗口，托盘菜单也提供入口；快速窗口沿用解析后明确确认的语义，并与主窗口共享资金 writer，操作见[系统与 AI 指南](system-and-ai.md)。

成功状态在数据库提交后显示，余额和列表随后刷新。失败会保留原文与表单；保持同一保存意图重试时复用请求标识，避免重复记账。发生版本冲突时先刷新并核对最新记录；修改意图后再明确保存。

本地规则不使用 AI。自然语言保存的记录保留原输入及 `local_rule` 来源，手工录入采用 `manual` 来源。可选 AI 需自行启用并明确点击“AI 解析”，返回待核对草稿，确认后保存为 `ai_assisted`；默认关闭，快速窗口仍采用本地规则。之后编辑记录时保留原类型、来源及原文，不能通过编辑将支出改成收入。

## 多笔、歧义与时间

```text
昨天吃饭128，朋友转我50
买咖啡25打车40
花128元，优惠20元
```

前两句保留两个独立候选，先从下拉列表选择本次要保存的一笔，核对并确认，再选择剩余候选；一次确认只保存一笔。程序不会把多金额相加或自动保存全部候选。第三句金额关系不清楚，会提示歧义，需修改原文或切换手工录入，不能仅取第一金额。

“下午3点花25”中的时间数字不会成为金额；已有具体时刻按当前 IANA 时区转换为 UTC。夏令时导致重复或不存在的当地时刻需要处理，不自动猜测。未来日期不能保存，同日未来精确时刻也会在资金服务提交时被拒绝。金额精度、范围和日期在保存时再次校验。

转账与退款使用专用表单；自然语言中的相关描述会提示操作类型。对“大约”“左右”等金额或其他无法确定的信息，应填写实际值后确认。保守规则可能无法识别复杂语句、未知商户或地点，可随时使用手工录入。

## 交易查询、编辑与删除

“交易记录”支持按账本、资金账户、分类、标签、类型和可选日期范围筛选，搜索备注、对象、商户、地点、原文及相关资料名称。点击“筛选 / 刷新”应用选择，文本搜索也可按 Enter。每页 50 笔，按业务日期、创建时刻和标识倒序显示；选择一行后操作。

收入和支出可以编辑金额、账户、账本、日期、分类等字段；转账和退款打开各自表单。修改带有原版本检查，记录已被其他操作更改时会提示冲突。保留原归档资料的历史交易可继续编辑，改变引用时必须选择可用项。

删除采用软删除，确认后从余额与收支中移除相应影响，历史审计仍保留。勾选“显示已删除”后可选择并恢复；恢复时重新校验账户起算日期、退款额度及其他资金规则。恢复原支出不会同时恢复相关退款。

期初记录不能在普通交易页面编辑、删除或恢复，应使用“修改期初”。校准记录的资金差额不能通过编辑改写，只可编辑说明；需要改变当前余额时进行新的余额校准。

## 转账、退款、期初与校准

| 操作 | 入口与填写 | 资金规则 |
| --- | --- | --- |
| 账户转账 | “账户与管理”选择账户类型，点击“账户转账”；填写转出/转入账户、正金额和日期 | 两个账户不同，两侧共同提交；不改变总资产，不计收入或支出 |
| 支出退款 | “交易记录”选择有效支出，点击“退款”；核对原支出、到账账户、金额和退款日期 | 可部分退款，可到账其他账户；活跃累计退款不超过原支出，日期不早于原支出 |
| 修改期初 | “账户与管理”点击“修改期初”；填写起算日期和期初金额 | 切点不能越过已有有效交易；零期初仍保存起算日期，负期初允许 |
| 余额校准 | “账户与管理”点击“余额校准”；填写当前实际余额和原因 | 仅校准今天；提交时按账户最新余额计算固定差额，保留原收支记录 |

原支出存在有效退款时，不能直接删除或迁移账本，也不能把金额降低至已退款金额以下。先检查关联退款，再作明确操作。退款的账本与分类继承原支出，不单独选择。

校准的目标是当前实际余额。对话框显示值不是资金权威，服务在写入事务中读取最新余额后计算差额；两者相同也记录本次确认。后续补录历史交易不会暗中重算旧校准差额。校准和期初不作为普通收入或支出。

## 首页金额口径

总资产是全部账户有效流水的余额总和，包括归档账户，不受当前账本筛选影响。本月收入只计算收入，本月净支出为当月支出减去当月实际到账退款；原支出可能发生于其他月份。退款较多时净支出可以为负。转账、期初和余额校准不计入月度收支。

首页提供基础汇总；完整趋势图、分类占比、消费排行和财务报告在“统计分析”查看。CSV/XLSX 导入导出、批次撤销及 PDF/PNG 报告已接入，详见[统计与数据交换指南](analysis-and-exchange.md)。可选 AI、系统主题、全局快捷键和手动更新检查见[系统与 AI 指南](system-and-ai.md)。附件录入、插件市场和实际云同步尚未实现。

## 主题、时区和备份

“设置”提供浅色、深色、跟随系统与有效 IANA 时区选择，界面语言可选择简体中文或英语，在下次启动生效。初始记账时区为 `Asia/Shanghai`，草稿旁显示当前值；它不是根据中文界面或 Windows 用户名推断的结果。更改时区不会改写历史交易的业务日期或时区，但会改变新交易及“今天/昨天”的解释。

桌面偏好保存在 `settings.json`，采用完整文件原子替换。资金备份包含数据库、审计和回执，不包含桌面偏好、AI 配置、更新仓库、API 凭据或未保存草稿。恢复到新目录后，先重新核对设置，再继续记账；维护命令见[备份恢复指南](../development/backup-recovery.md)。
